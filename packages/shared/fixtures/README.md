# Curve fixtures

`curve.json` is **generated by the Foundry project** (`contracts/script/GenerateFixtures.s.sol`
or a test using `vm.writeJson`) and checked in. It is the single source of truth proving that
the TypeScript mirror in `src/curve.ts` reproduces `MindLaunchpad.quoteBuy` / `quoteSell`
bit-for-bit (SPEC §1).

```sh
export PATH=/root/.foundry/bin:$PATH FOUNDRY_SOLC=/usr/local/bin/solc
cd contracts && forge script script/GenerateFixtures.s.sol   # writes ../packages/shared/fixtures/curve.json
cd ../packages/shared && pnpm test                           # vitest picks it up automatically
```

When the file is absent the vitest suite prints a notice and skips the equivalence test; the
self-contained property tests still run.

## Format

Either a bare array of cases or an object `{ "tradeFeeBps": "100", "cases": [...] }`.
Values may be decimal strings (preferred, since they exceed 2^53) or JSON numbers.

```json
{
  "tradeFeeBps": "100",
  "cases": [
    { "realEthReserve": "0", "tokensSold": "0", "op": "buy", "amountIn": "1000000000000000000",
      "tokensOut": "...", "ethUsed": "1000000000000000000", "fee": "10000000000000000" },
    { "realEthReserve": "...", "tokensSold": "...", "op": "sell", "amountIn": "<tokensIn>",
      "ethOut": "...", "fee": "..." },
    { "realEthReserve": "...", "tokensSold": "...", "op": "complete", "amountIn": "<ethIn>",
      "tokensOut": "<remaining supply>", "ethUsed": "...", "fee": "..." }
  ]
}
```

| field | meaning |
|---|---|
| `realEthReserve`, `tokensSold` | curve state **before** the operation |
| `op` | `buy`, `sell` or `complete` (a buy that sells out the curve; the test additionally asserts `completes`) |
| `amountIn` | `ethIn` (wei) for `buy`/`complete`, `tokensIn` for `sell` |
| `tokensOut` / `ethOut` | output of the quote |
| `ethUsed` | buys only: ETH consumed including fee (`< amountIn` only on a completing buy) |
| `fee` | total fee taken |
| `tradeFeeBps` | optional per-case override of the fee used for the quote |

At least 40 cases are expected, covering plain buys, sells, and completing buys with refund.

Rounding note for `complete` cases: on the completing buy the TS mirror computes
`net' = ceilDiv(k, y - remaining) - x`, `fee' = ceilDiv(net'·f, 10000 - f)` and then clamps
`ethUsed = min(net' + fee', ethIn)` (with `fee = ethUsed - net'`). Without the clamp a buyer
sending exactly the minimal completing amount would be charged `ethIn + 1` wei (negative
refund). The contract must produce the same `(tokensOut, ethUsed, fee)`; include a few cases
at `ethIn = minimalCompletingEth - {0,1,2}` so the fixture pins this down.
